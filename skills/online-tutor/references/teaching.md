# Plan and check a lesson

## Read and assess the source

Read the complete source before drafting. Identify its central claim, evidence, procedure, unfamiliar terms, and optional details.

Use the evidence in the source body when its summary disagrees. Report that disagreement. Do not make an uncertain claim appear certain.

For MEDIUM or HIGH work, record the reader's starting knowledge, motivation, reading environment, time budget, and cost of misunderstanding.

Also record the terms they already know, the primary takeaway, and details they can omit. Use those choices to set the explanation's depth.

For medical, legal, financial, religious, or safety-related content, distinguish source claims from uncertainty and professional advice.

## Prioritize content

| Priority | Content | Treatment |
|---|---|---|
| P0 | Primary claim, supporting reason, required steps | Explain first with an example |
| P1 | Useful evidence and necessary terms | Include within the lesson budget |
| P2 | Exceptions and secondary details | Include briefly or defer |
| P3 | Background unnecessary for this reader | Remove unless requested |

If every item appears essential, reassess the reader's goal. Keep unnecessary background out of the opening three sentences.

## Design the lesson

State the learning objective and why the original source needs a different explanation. Select three to seven concrete delivery principles.

Create a lesson map with each section's purpose, format, new concepts, and comprehension check. Keep each map row to one or two lines.

Use this order when applicable:

1. Explain the reader's task and why it matters.
2. State the primary idea.
3. Give one concrete example.
4. Explain the mechanism.
5. Give a comprehension check and its answer.
6. Connect the section to the next idea.

Omit inapplicable steps rather than adding filler. For a short task, merge overlapping sections and state the merge when useful.

For each lesson section, record:

| Field | Required content |
|---|---|
| Idea | One concept to learn |
| Example | A concrete case that shows the concept |
| Check | A question, prediction, or two-minute task |
| Answer | The explanation immediately after the check |
| Recovery | What to reread if the reader cannot answer |

For MEDIUM and HIGH work, put a recovery sentence after each answer in the explanation.

Tell the reader which example or section to reread if they cannot answer the question.

Introduce only a few new concepts at once. About four unfamiliar items is a planning heuristic, not a universal capacity limit.

If a section needs a second distinct idea, split it. Keep the lesson model within ten rows unless the source requires a longer course.

Record significant choices, such as a section split, diagram, removed story, or assumed term. Use decision, options, choice, and reason columns.

## Select the visual

Use a diagram only for structure, sequence, branches, or hierarchy that prose cannot explain as clearly.

Use plain ASCII, or box-drawing characters when Unicode support is known. Keep the width near 70–80 characters.

Use three to seven nodes. Split larger structures. Use at most one diagram per lesson section.

Label boxes and arrows. Put the diagram in a code block. State why the diagram helps.

Use tables for parallel comparisons. Keep a simple relationship in a sentence when a diagram adds no value.

## Select the example

Use a story when a concrete sequence clarifies a process or an unexpected result. Skip stories in searchable reference material.

Keep an opening scenario within two to four sentences. Do not delay the primary claim beyond the first paragraph.

Use at most one story per section. Connect it to the lesson in the same paragraph or the next paragraph.

Use only verified source behavior in factual examples. Label fictional inputs and people. Do not invent supporting evidence.

## Check the voice

Use specific words and concrete evidence. Remove unsupported praise such as “powerful” or “seamless.”

Reread the lesson as the intended reader. Rewrite sentences that require knowledge the reader does not have.

Define a necessary term once. Use the same term consistently. Do not explain a term that the reader already knows without a reason.

Use numbered steps for procedures. Use a bulleted list for parallel items. Keep causal reasoning in connected prose.

## Resolve blocking questions

Pause when missing reader context changes the lesson substantially. Also pause when contradictory or questionable source claims require a choice.

If the source needs several lessons, agree on the format when the request does not specify it.

Keep uncertainty visible in sensitive topics.

Do not use clear language to imply unsupported professional authority. Resolve the issue, ask a focused question, or report the limit.

## Review

Check these areas before delivery:

- The opening states the reader's primary takeaway.
- Each section teaches one idea with a concrete example.
- New terms match the reader's knowledge.
- Each required check tests that section's idea.
- The answer follows the check immediately.
- A recovery sentence tells the reader what to reread.
- Every diagram has a purpose and a portable format.
- Each story explicitly supports the lesson.
- Claims do not exceed the source evidence.
- The output stays within the selected budget.

For MEDIUM and HIGH work, score reader clarity, section size, examples, terms, checks, and source accuracy from one to five.

Score diagrams and stories only when used. Revise any required area below four. A self-score is an editing aid, not evidence of measured learning.

For HIGH work, prepare a comprehension test plan. MEDIUM work can also benefit from one.

| Prompt | Success | Correction if unsuccessful |
|---|---|---|
| State the primary idea | The reader states the takeaway in their own words | Move the takeaway earlier |
| Explain the second paragraph | The reader explains its meaning | Add a concrete example |
| Predict a changed input | The reader applies the concept | Explain the mechanism more clearly |
| Identify the unclear sentence | The reader locates the difficulty | Split or define the missing term |

## Deliver and get review

Return the explanation and approximate reading time. Identify the lesson count, source limits, resolved questions, and useful next action.

For a course, include the lesson map, glossary, significant decisions, and comprehension test plan. Check that tables and diagrams fit the destination.

Get explicit review for HIGH, domain-sensitive, or disputed-source work. Make sure that each blocking question has a resolution before final delivery.

Clear approval counts. Silence does not. Drafting approval does not authorize external publication.

## Project context

Read the available style guide, glossary, audience profile, destination format, and checkpoint mechanism. Use project-specific values rather than placeholder examples.

For a dense report, focus on the decision the reader needs. For research, explain the demonstrated mechanism before background detail.

For an unclear previous answer, rebuild the explanation around the reader's need. Do not merely shorten the same sentences.

For a long onboarding document, use separate lessons with individual checks. Keep each lesson understandable without the full reference document.

The original skill draws on worked examples, limited working memory, retrieval practice, and reader expertise. These methods guide design without guaranteeing retention.
